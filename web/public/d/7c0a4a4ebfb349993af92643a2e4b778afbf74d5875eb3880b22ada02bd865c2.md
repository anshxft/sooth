## NEAR Storage Staking Explainer

When you interact with a smart contract on NEAR, the protocol does not store data for free. Every byte that a contract keeps on‑chain must be paid for by the account that caused the data to be stored. This mechanism is called **storage staking**: the account “stakes” (locks) a certain amount of NEAR to cover the rent of the stored bytes. The locked NEAR cannot be spent while the data remains, but it can be reclaimed when the contract releases the space.

### How storage is priced

NEAR charges a flat rate per 100 kB of storage. As of the latest protocol release the price is **0.00125 NEAR per 100 kB** (≈ 12.5 yoctoNEAR per byte). The runtime converts this price into a number of yoctoNEAR that must be attached to a transaction. When a contract writes `n` bytes, it multiplies `n` by the per‑byte cost and requires that amount to be attached as a deposit. The attached NEAR is then **locked** in the contract’s balance; it is not burned, it simply cannot be transferred until the contract releases the corresponding storage.

### Why contracts ask for a deposit

A contract asks for a deposit to guarantee that the storage it uses is paid for. Without this guarantee a malicious user could fill a contract with huge maps or vectors, causing the network to store data forever for free. By requiring a deposit, the contract makes the cost of storage explicit and gives the user a way to retrieve the funds later.

### Payable method that charges for storage (Rust, near‑sdk)

```rust
#[payable]
pub fn register_account(&mut self, account_id: AccountId) {
    // Each registration stores a small struct (~48 bytes)
    let required_bytes = 48u64;
    // Current per‑byte cost from the runtime
    let byte_cost = env::storage_byte_cost(); // yoctoNEAR per byte
    let required_deposit = required_bytes * byte_cost;

    // Ensure the caller attached enough NEAR
    assert!(
        env::attached_deposit() >= required_deposit,
        "Insufficient deposit for storage"
    );

    // Record the account
    self.accounts.insert(&account_id, &AccountInfo::default());

    // Refund any excess deposit
    let excess = env::attached_deposit() - required_deposit;
    if excess > 0 {
        Promise::new(env::predecessor_account_id()).transfer(excess);
    }
}
```

The method calculates the exact amount of NEAR needed to lock for the bytes it will store, checks the attached deposit, stores the data, and refunds any surplus.

### Reclaiming locked NEAR

When a user no longer needs the stored data, the contract can release the space and return the locked NEAR. A common pattern is to provide a `storage_withdraw` or `storage_unregister` method:

```rust
pub fn storage_unregister(&mut self) {
    let account = env::predecessor_account_id();
    assert!(self.accounts.remove(&account).is_some(), "No data");
    // Compute how many bytes are being freed
    let freed_bytes = 48u64;
    let refund = freed_bytes * env::storage_byte_cost();
    Promise::new(account).transfer(refund);
}
```

Calling this function removes the user’s entry, frees the bytes, and transfers the previously locked NEAR back to the user’s account. As long as the contract correctly tracks the byte count, users can always retrieve the exact amount they originally staked.
