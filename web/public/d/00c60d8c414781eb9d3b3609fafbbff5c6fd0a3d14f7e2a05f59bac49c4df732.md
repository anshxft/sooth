# NEAR Function‑Call Key Explainer

## What is a function‑call access key?

A function‑call access key is a special type of NEAR access key that can only be used to invoke a predefined set of contract methods. When the key is created, the contract ID, the list of allowed method names, and optional gas and allowance limits are recorded on‑chain. Any transaction signed with that key that tries to call a method outside the whitelist will be rejected by the protocol. This makes the key **read‑only for the specified functions** and prevents an AI agent (or any holder of the private key) from performing arbitrary actions such as transferring the whole balance, adding new keys, or calling `delete_account`.

## How it restricts an AI agent’s wallet actions

- The AI can only submit transactions that match the whitelisted method names.  
- The key cannot be used to sign a generic `Transfer` or `DeployContract` transaction.  
- Gas and attached token allowance can be capped, limiting how much the AI can spend in a single call.

Because the restrictions are enforced by the blockchain itself, the AI cannot bypass them without the holder’s explicit permission.

## Concrete example

Assume a wallet wants to let an AI agent manage its fungible‑token (FT) balance but only allow transfers to a known marketplace contract.

```json
{
  "public_key": "ed25519:...",
  "access_key": {
    "permission": {
      "FunctionCall": {
        "receiver_id": "example-token.near",
        "allowance": "0.5 NEAR",
        "method_names": ["ft_transfer"]
      }
    }
  }
}
```

With this key the AI can call `ft_transfer` on the `example-token.near` contract, e.g.:

```rust
contract.ft_transfer(
    receiver_id: "marketplace.near",
    amount: "10",
    memo: "Purchase"
);
```

The AI **cannot** call any other method such as `ft_transfer_call`, `storage_deposit`, or a generic `transfer` of NEAR tokens.

## Remaining risks (exactly two)

1. **Allowance exhaustion or gas limits** – If the allowance or gas cap is set too high, the AI could still move a large amount of tokens in a single permitted call, effectively draining the wallet of the specific asset the key controls.
2. **Re‑entrancy or contract‑level bugs** – The allowed method (`ft_transfer`) may internally call other contracts or contain logic flaws. An attacker controlling the AI could exploit such bugs to cause unintended side effects (e.g., double‑spend via a vulnerable token contract) even though the key itself is limited to `ft_transfer`.
