# SOOTH contract interface — v1.0 (frozen 27 Oct 2026)

The single contract between the Rust contract (`contracts/sooth`), the agent runtime (`agents/`) and the web app (`web/`). Mock data in [`mock/`](../mock) follows these shapes exactly and is generated by [`mock/make_mock.py`](../mock/make_mock.py), which also checks the payout math.

Changing anything here after 1 Nov means: update this file, the mock generator, and both consumers in the same commit.

Scope: register + stake, ask, commit/reveal, tally with automatic round 2, finalize with payouts, plus agent bots on function-call keys. Items marked *(Should)* or *(Stretch)* are frozen in shape but may ship later.

---

## 1. Conventions

| Thing | Rule |
| --- | --- |
| NEAR amounts | `U128` = decimal string in yoctoNEAR (`"1000000000000000000000000"` = 1 NEAR) |
| Weights | `U128` string, in "weighted yoctoNEAR" (see §5) |
| Timestamps | `U64` = decimal string, **nanoseconds** since Unix epoch (NEAR block time) |
| Durations | plain JSON numbers, **seconds** |
| Question id | JSON number (`u64` counter starting at 1; stays far below 2^53) |
| Percent-like values | integer **basis points** (`bps`, 10 000 = 100 %) — no floats on-chain |
| Confidence | integer `1..=99` (percent) |
| Hashes | 64-char **lowercase hex** sha256 |
| Errors | contract panics with the exact strings in §8 |

## 2. Config and constants

```ts
interface Config {
  owner: string
  dao_account: string            // MVP: same as owner; Sputnik DAO later (Stretch)
  treasury: string
  protocol_fee_bps: number       // 500  (5 %)
  min_agents: number             // 3    revealed agents needed for auto-resolve
  max_commits: number            // 30   per round, bounds gas in tally
  auto_share_bps: number         // 8000 winning weight share needed for auto-resolve
  auto_conf_bps: number          // 7000 weighted avg confidence of the winning side
  default_timings: Timings
  min_fee: U128                  // 0.1 NEAR
  question_storage: U128         // 0.1 NEAR, non-refundable, covers the question itself
  agent_storage: U128            // 0.05 NEAR, non-refundable
  commit_storage: U128           // 0.005 NEAR per commit, taken from the agent's free balance (no deposit)
}

interface Timings { commit_secs: number; reveal_secs: number; challenge_secs: number }
// default_timings = { commit_secs: 180, reveal_secs: 120, challenge_secs: 180 }  (demo values)
```

Storage is measured, not guessed: the worst-case round (30 agents with 56-char account ids, 280-char text, 500-char params, 300-char evidence URIs) writes 19 326 bytes = 0.194 NEAR, inside the 0.1 + 30 × 0.005 = 0.25 NEAR budget (test `full_round_fits_the_storage_budget`). Timings: every phase 30 s – 7 days.

## 3. Types

```ts
type U128 = string
type U64 = string
type Answer = 'YES' | 'NO' | 'INVALID'
type Category = 'crypto' | 'weather' | 'sports' | 'news'
type Template = 'crypto_price' | 'weather_rain' | 'free_text'

// Stored on-chain.
type Status = 'Open' | 'Provisional' | 'Escalated' | 'Finalized' | 'Refunded'
// Derived in views from status + block time (what the UI shows).
type Phase =
  | 'Scheduled'        // Open, now < commit_start (event not over yet)
  | 'Commit'           // Open, commit_start <= now < commit_end
  | 'Reveal'           // Open, commit_end <= now < reveal_end
  | 'AwaitingTally'    // Open, now >= reveal_end, nobody called tally yet
  | 'Challenge'        // Provisional, now < challenge_end
  | 'AwaitingFinalize' // Provisional, now >= challenge_end
  | 'Dao'              // Escalated
  | 'Finalized'
  | 'Refunded'

interface AgentStats {
  answered: number   // revealed answers that were settled (correct + wrong)
  correct: number
  wrong: number
  no_reveal: number
  earned: U128       // lifetime rewards
  slashed: U128      // lifetime slashes
}

interface AgentView {
  account_id: string
  name: string
  model: string
  registered_at: U64
  free_balance: U128     // withdrawable, usable for new commits
  locked_balance: U128   // stakes in unsettled questions
  rep_bps: number        // 5000..=20000, see §5
  accuracy_bps: number   // smoothed: (correct+1)/(answered+2)
  stats: AgentStats
}

interface CommitView { account_id: string; hash: string; stake: U128; committed_at: U64 }

interface RevealView {
  account_id: string
  answer: Answer
  confidence: number
  evidence_hash: string
  evidence_uri: string
  rep_bps: number        // snapshot at reveal; used for weight and reward
  weight: U128
  revealed_at: U64
}

interface TallyView {
  weights: Record<Answer, U128>
  winner: Answer | null  // null on an exact tie
  share_bps: number
  avg_conf_bps: number
  revealed: number
  confident: boolean
  tallied_at: U64
}

interface RoundView {
  round: 1 | 2
  min_stake: U128        // round 2 = 2 × round 1
  commit_start: U64      // round 1: max(created_at, resolve_after)
  commit_end: U64
  reveal_end: U64
  commits: CommitView[]
  reveals: RevealView[]  // only revealed agents; order = reveal order
  tally: TallyView | null
}

interface Outcome {
  answer: Answer
  share_bps: number
  avg_conf_bps: number
  resolved_by: 'auto' | 'round2' | 'dao'
}

interface Payout {
  account_id: string
  round: 1 | 2           // an agent can have a commit in both rounds; each is settled on its own
  stake: U128
  delta: string          // signed yocto, e.g. "-990000000000000000000000"
  reason: 'correct' | 'wrong' | 'no_reveal' | 'challenge_won' | 'challenge_lost'
}

interface QuestionView {
  id: number
  asker: string
  text: string
  category: Category
  template: Template
  params: string         // template params as a JSON string, opaque to the contract (≤ 500 chars)
  fee: U128
  created_at: U64
  resolve_after: U64
  timings: Timings
  status: Status
  phase: Phase
  round: 1 | 2
  rounds: RoundView[]
  challenge_end: U64 | null
  challenger: { account_id: string; bond: U128 } | null   // (Should, F9)
  outcome: Outcome | null
  payouts: Payout[]      // empty until Finalized
  protocol_fee: U128 | null
  dust: U128 | null      // rounding remainder, sent to treasury
  finalized_at: U64 | null
  callback: { contract_id: string; method: string } | null // (Should, F13)
}

interface QuestionSummary {
  id: number
  text: string
  category: Category
  status: Status
  phase: Phase
  round: 1 | 2
  fee: U128
  resolve_after: U64
  phase_ends_at: U64 | null   // end of the current phase, for countdowns
  commits: number             // current round
  reveals: number             // current round
  outcome: Outcome | null
}

interface ResultView {
  question_id: number
  answer: Answer
  share_bps: number
  avg_conf_bps: number
  resolved_by: 'auto' | 'round2' | 'dao'
  finalized_at: U64
}
```

Template params:

| Template | `params` example |
| --- | --- |

## 4. Methods

`FC` = callable with the agent's function-call key (method list `["commit","reveal"]`, receiver = SOOTH contract, allowance 0.25 NEAR). Function-call keys cannot attach deposits (verified on testnet, 26 Oct).

### Change methods

| Method | Caller / key | Deposit | Does | Event |
| --- | --- | --- | --- | --- |
| `new(owner, dao_account, treasury)` | deployer | — | init with default config | — |
| `register_agent(name, model)` | agent, full key | ≥ `agent_storage`; excess → free balance | creates profile; `name` 2–32 chars `[a-z0-9_-]`, `model` ≤ 64 chars | `agent_registered` |
| `deposit_stake()` | agent, full key | any > 0 | free balance += deposit | `stake_deposited` |
| `withdraw_stake(amount: U128)` | agent, full key | **exactly 1 yoctoNEAR** (refunded with the transfer) | free balance −= amount, transfer. The 1 yocto rule means a function-call key can never call it, even if allow-listed by mistake | `stake_withdrawn` |
| `ask_question(text, category, template, params, resolve_after: U64, min_stake: U128, timings?: Timings, callback?)` → `number` | anyone | `fee + question_storage`, fee ≥ `min_fee` | creates question; text 10–280 chars | `question_created` |
| `commit(question_id, hash, stake: U128)` | agent, **FC** | **0** | phase must be `Commit`; one commit per agent per round; `stake ≥ min_stake`; moves stake free → locked and takes `commit_storage` from free | `committed` |
| `reveal(question_id, answer, confidence, evidence_hash, evidence_uri, salt)` | agent, **FC** | **0** | phase must be `Reveal`; checks hash (§6); stores weight with rep snapshot | `revealed` |
| `tally(question_id)` | anyone (crank) | — | phase `AwaitingTally`; see flow below | `tallied` |
| `challenge(question_id)` *(Should)* | anyone | bond = 2 × fee (round 1), 4 × fee (round 2) | phase `Challenge`; round 1 → starts round 2, round 2 → `Escalated` | `challenged` |
| `finalize(question_id)` | anyone (crank) | — | phase `AwaitingFinalize`; payouts (§5), stats, callback | `finalized` |
| `dao_resolve(question_id, answer)` | `dao_account` only | — | phase `Dao` → payouts against `answer` | `finalized` |

**Tally flow** (round = current round):

1. 0 reveals in round 1 → `Refunded`: fee back to asker, non-revealers slashed to treasury. *(Replaces the separate `refund` method from the spec.)*
2. `confident` (share ≥ 8000, avg conf ≥ 7000, revealed ≥ 3, no tie) → `Provisional`, `challenge_end = now + challenge_secs`.
3. Not confident in round 1 → round 2 starts now with `min_stake × 2` (all round-1 stakes stay locked).
4. Not confident in round 2 → `Escalated`.

### View methods

| Method | Returns |
| --- | --- |

| `get_agent(account_id)` | `AgentView \| null` |
| `list_agents(from_index: number, limit: number)` | `AgentView[]` (registration order, limit ≤ 50) |

## 5. Math (integers, exactly what `payout.rs` and `make_mock.py` implement)

```text
accuracy_bps = (correct + 1) * 10000 / (answered + 2)
rep_bps      = 5000 + 15000 * max(0, 2*(correct+1) - (answered+2)) / (answered+2)    // 5000..=20000

weight       = stake * rep_bps * confidence / (10000 * 100)                         // at reveal

share_bps    = winner_weight * 10000 / total_weight
avg_conf_bps = Σ_winner(weight_i * confidence_i) * 100 / winner_weight
confident    = share_bps >= 8000 && avg_conf_bps >= 7000 && revealed >= 3 && winner != null

// finalize, against the final answer, over every round's participants
slash        = wrong:      stake * confidence / 100
               no_reveal:  stake
protocol_fee = fee * 500 / 10000
pot          = fee - protocol_fee + Σ slash (+ lost challenge bond)
score        = stake * rep_bps * (10000 - (100 - confidence)^2)                      // correct only
reward_i     = pot * score_i / Σ score                                               // floor
dust         = pot - Σ reward_i                                                      // → treasury
if Σ score == 0: fee back to asker, Σ slash → treasury
```

All divisions floor. `pot × score` overflows u128 (≈ 10⁶⁰), so `reward_i` uses an exact 256-bit `mul_div` (`payout.rs`); any other implementation must also be exact or it will not match the test vector. Invariant (checked in tests, in `make_mock.py`, and in the contract before money moves): **`fee + Σslash = protocol_fee + Σreward + dust`** (plus refund in the no-winner case). Test vector: question 40 in `mock/questions.json`.

## 6. Commit hash and evidence

```text
preimage = "{question_id}|{round}|{agent_account_id}|{answer}|{confidence}|{evidence_hash}|{salt}"
hash     = lowercase_hex(sha256(utf8(preimage)))
salt     = 32 random hex chars, generated per commit, saved locally until reveal
```

`question_id` and `round` stop a commit being replayed in another question or round; the account id stops copying (proven in `spike-fc`).

Evidence document, uploaded before commit to a public URL (`evidence_uri`):

```ts
interface EvidenceDoc {
  version: 1
  question_id: number
  round: 1 | 2
  agent: string
  model: string
  answer: Answer
  confidence: number
  reasoning_summary: string        // ≤ 2 sentences
  sources: string[]                // URLs
  data_fact: { source: string; fact: string } | null
  created_at: string               // ISO 8601 UTC
}
```

`evidence_hash = sha256` of the **exact uploaded bytes** (never re-serialise before hashing). The web app fetches `evidence_uri` and recomputes the hash with WebCrypto to show "hash matches on-chain".

## 7. Events (NEP-297)

Logged as `EVENT_JSON:{"standard":"sooth","version":"1.0.0","event":"<name>","data":[{...}]}`.

| Event | `data[0]` |
| --- | --- |
| `agent_registered` | `{account_id, name, model}` |
| `stake_deposited` / `stake_withdrawn` | `{account_id, amount}` |
| `question_created` | `{question_id, asker, category, fee, resolve_after}` |
| `committed` | `{question_id, round, account_id, stake}` |
| `revealed` | `{question_id, round, account_id, answer, confidence, weight}` |
| `tallied` | `{question_id, round, result: "provisional" \| "round_started" \| "escalated" \| "refunded", winner, share_bps, avg_conf_bps}` |
| `challenged` | `{question_id, round, challenger, bond}` |
| `finalized` | `{question_id, answer, resolved_by, payouts: Payout[], protocol_fee, dust}` |

The activity feed ("mallory slashed 0.99 NEAR") is built from `finalized.payouts`.

## 8. Error strings

| Method | Panic message |
| --- | --- |
| any agent method | `Agent not registered` |
| `register_agent` | `Already registered`, `Attach at least the agent storage deposit`, `Invalid agent name`, `Model must be 1-64 chars` |
| `deposit_stake` | `Attach a deposit` |
| `withdraw_stake` | `Requires attached deposit of exactly 1 yoctoNEAR`, `Amount must be positive` |
| `withdraw_stake`, `commit` | `Insufficient free balance` |
| `ask_question` | `Fee below minimum`, `Text must be 10-280 chars`, `Params too long`, `Invalid timings`, `Min stake must be positive` |
| `commit` | `Not in commit phase`, `Already committed this round`, `Stake below round minimum`, `Hash must be 64 lowercase hex chars`, `Round is full` |
| `reveal` | `Not in reveal phase`, `No commit found`, `Already revealed`, `Confidence must be 1-99`, `Hash must be 64 lowercase hex chars` (evidence hash), `Evidence URI too long` (> 300), `Hash mismatch` |
| `tally` | `Not ready to tally` |
| `challenge` | `Not in challenge phase`, `Bond too small` |
| `finalize` | `Not ready to finalize` |
| `dao_resolve` | `Only the DAO can resolve`, `Question is not escalated` |
| any | `Question not found` |

## 9. Changes vs SOOTH_SPEC v0.1

- `refund` method folded into `tally` (0 reveals → `Refunded`).
- Commit preimage now includes `question_id` and `round` (spec had it; spike used the short form).
- `round` max is 2; escalation after round 2 goes to `dao_account` (owner in MVP).
- Weight stored at reveal with a rep snapshot, so tally never re-reads agent stats.
- `template` + `params` added to questions so agents get structured inputs (agent spike, 27 Oct).
